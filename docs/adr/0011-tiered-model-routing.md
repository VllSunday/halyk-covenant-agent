# Каскад моделей по цене ошибки

## Контекст

Один полный прогон на Sol оказался слишком дорогим для многократной проверки. При
этом роли отличаются по сложности: отнесение операции к статье требует чтения
короткой строки, а перевод пункта договора в Formula AST влияет сразу на весь
расчёт заёмщика. Одна модель для всех ролей либо переплачивает за простые задачи,
либо снижает точность на дорогих по последствиям шагах.

## Решение

Зафиксирована маршрутизация по роли:

- OCR — `gpt-5.6-terra`, `low`;
- первичная классификация операций — `gpt-5.6-luna`, `medium`;
- проверка спорной классификации — `gpt-5.6-terra`, `medium`;
- компилятор ковенантов — `gpt-5.6-terra`, `high`;
- resolver фактов — `gpt-5.6-terra`, `high`;
- эскалация невалидного или незавершённого ответа компилятора и resolver —
  `gpt-5.6-sol`, `high`.

Sol не вызывается при сетевой ошибке, исчерпанном балансе или превышении бюджета:
другая модель того же провайдера не устраняет эти причины. Кэш адресуется моделью,
ролью, уровнем reasoning, промптом, схемой и входными документами, поэтому ответы
разных ступеней не смешиваются. Арифметика, вердикт и выбор улики остаются в
детерминированном Python-коде.

Бюджет считает каждый вызов по тарифу фактически выбранной модели. Неизвестный
model slug использует явно заданную запасную цену и не считается бесплатным.

## Отвергнутые варианты

Sol для всех ролей давал сильный baseline, но делал повторные тесты дорогими.
Luna для всех ролей экономила бы больше, однако ошибка компиляции меняет формулу,
порог и фильтры сразу для нескольких компонентов ответа. Terra без эскалации могла
бы оставить незакрытый термин или требование и сорвать строгий прогон целиком.

## Чем платим

Смена модели инвалидирует соответствующий кэш, поэтому первый прогон после
маршрутизации холодный. Каскад сложнее одного вызова и в худшем случае оплачивает
две попытки Terra до Sol. Цена ограничена общим бюджетом, а факт эскалации виден в
телеметрии по имени модели.
